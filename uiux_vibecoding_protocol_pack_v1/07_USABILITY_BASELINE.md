# 07_USABILITY_BASELINE: ユーザビリティ標準規約

## 1. 目的
この章は、UIの見た目ではなく、ユーザーが既存のOS・デスクトップアプリ経験から当然試す操作経路を欠落させないための規約である。

この規約は「なぜ・いつその操作品質が必要か」を定義する。Button、Form、Table、Dialogなどの部品固有の実装方法は `04_COMPONENT_RULES.md`、キーボード到達性やARIAは `06_ACCESSIBILITY_CHECKLIST.md`、最終的な横断検収は `08_REVIEW_CHECKLIST.md` で扱う。

原則は「ユーザーが既に持つ状態・対象・操作知識を捨てない」こと。画面上に既にある値、選択中の対象、前回使った場所、外部アプリ上にあるファイルやテキストを、次の操作の初期状態や入力経路として可能な限り利用する。

ユーザビリティは、機能や部品が存在することではなく、特定の利用文脈でユーザーが目的を正確・効率的・予測可能・安全に達成できることとして評価する。対象タスクに関係する範囲で、次を確認する。

- 有効性: 目的を最後まで正確に達成できる。
- 効率: 不要な入力、移動、記憶、待機、再操作を減らせる。
- 予測可能性: OS、プラットフォーム、一般的なアプリの経験から挙動を予測できる。
- 回復可能性: 誤操作、失敗、中断から作業状態を保って戻れる。
- アクセシビリティ: 入力手段や表示環境が変わっても基本目的へ到達できる。

「要求されていない」は、自然な操作経路を除外する単独の理由にしない。一方で、慣習的な機能を無条件に追加するのでもなく、対象タスクへの利益、誤操作、複雑性、保守負担、仕様・安全境界との釣合いで採否を判断する。

## 2. 標準操作経路の完備性
UI要素を実装するときは、仕様に明記された操作だけで完了判定しない。対象の性質から、ユーザーが自然に試す主要操作経路を列挙し、適用可否を判断する。

- 同じ意味の入力は、自然な範囲で複数経路から受け付ける。
- 外部または画面内に既に存在する対象は、直接操作を第一候補として検討する。
- キーボード、マウス、クリップボード、D&Dのうち、対象に自然なものを検討する。
- 適用可能なのに実装しない操作経路がある場合は、非対応理由を実装メモ又はレビュー結果に残す。

## 3. 文脈継承
ある操作が、画面上に既に存在する状態から開始されるなら、その操作の初期状態は可能な限り現在の状態から導出する。

- 入力済みの値、選択中の項目、現在表示中の範囲、直近の有効値、前回使用位置を次の操作へ渡す。
- コンポーネント境界を跨いだという理由だけで、ユーザーの作業文脈を捨てない。
- 無効な状態は無視して既定値へ飛ばすのではなく、有効な親状態や直近状態へフォールバックする。
- 日付、色、検索条件、出力先、選択項目、再実行パラメータは、次の編集・参照・保存・再実行の初期状態に反映する。

## 4. 対象別の標準入力経路
|対象|標準的に検討する経路|
|---|---|
|ファイル|手入力、paste、参照、D&D、最近使った場所|
|フォルダ|手入力、paste、参照、D&D、現在値からの参照開始|
|URL|入力、paste、URL文字列又はリンクのD&D|
|画像|参照、D&D、clipboard paste、preview|
|テキスト|入力、paste、選択範囲からの反映、Undo/Redo|
|一覧項目|クリック選択、キーボード選択、ダブルクリック、必要なら並べ替えD&D|

すべてを常に必須としない。ただし対象の性質上自然な経路を省く場合は、その理由を説明できる状態にする。

## 5. ファイル・フォルダ入力の既定
ファイル又はフォルダを受け取るUIでは、手入力、paste、参照ボタン、D&Dを標準候補として扱う。

参照ダイアログの開始位置は次の優先順で決める。

1. 現在入力値が存在するディレクトリなら、そのディレクトリ。
2. 現在入力値が存在するファイルなら、その親ディレクトリ。
3. 現在入力値が未存在でも親ディレクトリが存在するなら、その親ディレクトリ。
4. 直近の有効な選択先又は前回使用位置。
5. 作業対象プロジェクト、現在開いているファイル、又はOS既定位置。

入力値は可能な範囲で寛容に扱う。

- 前後空白、引用符付きパス、末尾スラッシュを吸収する。
- `/` と `\` の差を対象OSに合わせて正規化する。
- 無効入力時は、何が無効でどう直せるかをその場で示す。
- D&D可能領域は dragover / hover 中に視覚的に反応し、失敗時は理由を表示する。

## 6. 一覧・テーブル・選択UIの既定
一覧やテーブルは、見るだけでなく対象を選び、開き、編集し、コピーし、必要なら並べ替える作業領域として扱う。

- 行ダブルクリックは、その行の主要操作として自然かを検討する。
- Enterは選択項目の主要操作又は確定に割り当てることを検討する。
- Escは選択解除、編集中断、ダイアログ終了などの回復操作として検討する。
- Ctrl+A / Ctrl+C / Ctrl+V / Ctrl+Z は、対象に自然な場合に期待通り扱う。
- 選択、フォーカス、編集中、変更済み、処理中の状態を視覚的に区別する。

## 7. OS・デスクトップ慣習
PC優先の業務・管理・編集UIでは、OSや一般的なデスクトップアプリの操作語彙を再利用する。

- Enter: 確定、開く、実行。
- Esc: 閉じる、キャンセル、選択解除。
- Ctrl/Cmd+C: 選択中内容のコピー。
- Ctrl/Cmd+V: 対象に自然な貼り付け。
- Ctrl/Cmd+A: 現在スコープ内の全選択。
- Ctrl/Cmd+Z / Shift+Ctrl/Cmd+Z: Undo / Redo。
- Double click: 項目を開く、主要操作を実行。
- Drag and drop: 外部又は画面内の対象を渡す、又は並べ替える。

ブラウザ、Electron、ネイティブアプリなど実行環境によって制約がある場合は、実装可能な範囲と代替操作を明記する。

## 8. 検収時の確認
実装後又はレビュー時は、画面を初見で操作するユーザーが「当然できる」と試しそうな操作を列挙し、実装済みか確認する。

特にファイル/フォルダ入力では、少なくとも `入力 / paste / 参照 / D&D / 現在値から参照開始` を確認する。未対応がある場合は、仕様上不要なのか、技術制約なのか、実装漏れなのかを分類する。

最後に、実装した機能の動作だけで判定せず、自然な操作の欠落を次の順で確認する。

1. ユーザーが対象を見て最初に試しそうな操作は何か。
2. OSや同種アプリで定着した操作のうち、適用可能なものは何か。
3. 同一目的に対してマウス以外の入力経路が必要か。
4. システムが既に知っている値、選択、位置、検索条件を再入力させていないか。
5. 状態、対象範囲、処理中・保存済み・失敗などの結果が認識できるか。
6. 誤操作、失敗、中断から戻れるか。

確認結果は、確認済み・修正済み・未確認に分ける。AIが「使いやすい」と説明したこと自体は検収証拠にせず、実環境での操作、コード上の根拠、又は未確認理由を示す。

## 9. 操作カテゴリ別の追加基準

### 9.1 選択・編集
- 単一選択、複数選択、範囲選択、全選択を対象に応じて検討する。
- 選択、フォーカス、編集中、変更済みを混同させず、選択対象への作用範囲を明示する。
- 編集値を検証失敗だけで消さず、可能なら inline、context内、又は適切な side panel で編集できるようにする。
- 対象に自然なら Copy / Cut / Paste / Undo / Redo を提供し、外部変更や競合を黙って上書きしない。

### 9.2 ナビゲーション・検索・一覧
- 現在地、親階層、戻り先を認識でき、Back で直前の作業文脈へ戻れるようにする。
- 詳細画面から戻ったとき、検索、filter、sort、scroll、selection を必要に応じて保持する。
- Search / Filter / Sort は現在の条件、解除方法、結果0件、loading、古い非同期結果を区別する。
- Table / List / Tree / Grid は、選択、キーボード移動、コピー、並べ替え、一括操作を対象に応じて検討する。

### 9.3 フィードバック・エラー・回復
- accepted、working、progress、completed、failed、cancelled、unsaved、saved を必要に応じて区別する。
- エラーは「何が問題か」「なぜ進めないか」「どう直すか」を示し、入力を保持する。
- 重要な処理には Cancel / Stop / Retry を、破壊的変更には Undo / Restore 又は必要な確認を検討する。
- 自動処理、focus移動、scroll移動、再配置でユーザーの制御権や作業位置を奪わない。

### 9.4 フォーム・ダイアログ・永続化
- visible label、適切なcontrol、既知値のprefill、autocomplete、単位、入力保持を用い、同じ情報を同一セッションで再入力させない。
- Dialog は短時間の確認・警告・軽い入力に使い、呼出元への復帰、Escape、Cancel、処理中状態を検討する。
- 前回位置、window / panel サイズ、表示モードなどは、保存されることが自然で安全な状態だけを適切に継承する。意外な永続化は避ける。

### 9.5 表示環境・言語・入力方式
- 狭幅、拡大表示、タッチ、キーボード、支援技術、IME、日本語入力、RTLや長い翻訳文を対象環境に応じて確認する。
- マウス、キーボード、タッチ、ペン、支援技術のどれか一つだけを唯一の必須経路にしない。
