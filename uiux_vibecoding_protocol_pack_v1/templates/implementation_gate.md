## 統合ゲート：利用者起点・小2視点・ゼロベース改善

実装前に必要な情報を**一つの短い記録**へまとめる。既存チェックの転記・形式的な案の量産は禁止。小規模な変更は影響範囲の記録だけでよい。

```txt
設計・検収ゲート:
- 原初の要件・不変条件: ユーザー目的 / 必須機能 / 状態・保存 / 安全・権限
- 観察した不便と原因仮説: 迷い / 手戻り / 不要な記憶・入力 / 結果が見えない理由
- ゼロベースの解決方針: 削除・統合・直接操作・再配置・順序変更 / 必要な代替案
- 小2視点: 見れば分かる / 触れば変わる / 試せば結果が見える / 間違えても戻せる / 基本操作の組合せ
- 比較と採否: 原初要件の保持 / 実操作の負担 / 総複雑性 / リスク
- 検証: 代表タスクの入口→操作→結果→回復 / 証拠 / PASS・FAIL・UNVERIFIED・N/A
```

当該UIの標準操作、ショートカット表示、文脈内ヘルプ、アクセシビリティは `07_USABILITY_BASELINE.md` と `08_REVIEW_CHECKLIST.md` を参照し、同じチェックをここへ複製しない。未承認の仕様変更や危険操作は行わず、判断待ちは正本のOwnerへ分離する。

## 実装禁止条件
- 画面目的が不明。
- 主データ形式が不明。
- 危険操作の扱いが不明。
- 対象端末により根本レイアウトが変わるのに未確認。
- ユーザーがモック確認を求めているのにコードを書こうとしている。
