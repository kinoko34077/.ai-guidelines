# 07_REVIEW_CHECKLIST: UI検収チェックリスト

## 1. 情報設計
- 画面目的は1文で説明できるか。
- 主タスクは3〜5個に収まっているか。
- High/Medium/Lowの情報優先度が見た目に反映されているか。
- 主データよりボタンや装飾が目立っていないか。

## 2. 操作階層
- Primary Actionは原則1つか。
- Secondary/Tertiary/Row/Dangerが分離されているか。
- 同じ強さのボタンが横並びで3つ以上ないか。
- 行操作がグローバル操作のように見えていないか。
- 危険操作が通常操作の隣にないか。

## 3. 文言・アイコン
- 長文ボタンが常時表示されていないか。
- 「〜する」の冗長語尾を短語化できないか。
- icon-onlyにtooltipとaria-labelがあるか。
- 逆に、意味が伝わらないアイコンだけになっていないか。
- 説明文はhelper/tooltip/empty stateへ分離されているか。

## 4. レイアウト
- 上部、左、中央、右、行末の役割が混ざっていないか。
- カードUIが一覧性や比較性を壊していないか。
- サイドバーや右パネルが主作業領域を狭めすぎていないか。
- toolbarが二段折返しやボタン密集になっていないか。
- 狭幅時の退避先があるか。

## 5. フォーム
- inputにvisible labelがあるか。
- placeholderに意味を依存していないか。
- errorが具体的で回復可能か。
- 保存/キャンセル/削除の配置と強さが適切か。

## 6. 標準操作・文脈継承
- この画面を初見で操作するユーザーが「当然できる」と試しそうな操作を列挙したか。
- 実装された要素だけでなく、未実装の自然な操作経路を確認したか。
- ファイル/フォルダ入力で `入力 / paste / 参照 / D&D / 現在値から参照開始` を検討したか。
- 参照ダイアログ、カレンダー、色選択、保存先などが現在値・選択中項目・前回状態から開始されるか。
- Enter、Esc、Ctrl/Cmd+C/V/A/Z、ダブルクリックなどが対象に自然な場合に期待通り動くか。
- D&D可能領域が視覚的に反応し、失敗時に理由を示すか。
- 自然だが非対応にした操作がある場合、非対応理由が明記されているか。

## 7. 最終判定
|判定|条件|
|---|---|
|OK|重大違反なし。小修正のみ|
|要修正|主操作、密度、文言、配置、標準操作、アクセシビリティのどれかに明確な問題あり|
|差戻し|画面目的やレイアウト骨格から不適切|
